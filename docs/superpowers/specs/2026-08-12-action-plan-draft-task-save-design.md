# 조치계획 임시 과제 저장 설계

## 목표

조치계획 팝업의 마지막 입력 행에 과제명을 작성한 뒤 저장하면, 별도의 신규 과제 추가 버튼을 누르지 않아도 해당 과제가 조치계획 저장 요청에 포함된다.

## 동작

1. 기존 등록 과제는 현재처럼 `tasks` 목록에서 저장한다.
2. 마지막 입력 행의 과제명이 공백이 아니면 저장 직전에 임시 과제로 변환한다.
3. 임시 과제에는 현재 선택한 담당자와 마감일을 사용하며, 마감일 `미정`은 `null`로 보낸다.
4. 과제명이 비어 있으면 마지막 입력 행은 저장 요청에서 제외한다.
5. 신규 과제 추가 버튼의 기존 동작은 유지한다.

## 구현 범위

- `ActionPlan`의 저장 콜백에 마지막 입력 행의 값을 전달한다.
- 상위 저장 처리에서 기존 과제와 임시 과제를 합쳐 `tasks` 페이로드를 만든다.
- API 및 데이터베이스 스키마는 변경하지 않는다.

## 검증

- 임시 과제명, 담당자, `null` 마감일이 저장 페이로드에 포함되는 회귀 테스트를 추가한다.
- 빈 임시 과제명은 페이로드에 포함되지 않는지 테스트한다.
- 전체 테스트와 빌드를 실행한다.
