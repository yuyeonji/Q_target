# 조치계획 관리번호 분리 설계

## 목표

각 관리번호의 조치계획과 과제가 서로 섞이지 않게 하고, `저장 및 승인 요청`을 누를 때만 해당 관리번호의 현재 조치계획을 Neon DB에 저장한다.

## 사용자 동작

- `+ 신규 과제 추가`은 모달 안의 과제 목록에만 추가한다. DB에는 저장하지 않는다.
- `저장 및 승인 요청`은 선택된 관리번호와 연결된 현재 조치계획의 분석 내용과 전체 과제 목록을 한 번에 저장한다.
- 저장 후 F5하면 동일 관리번호에서 저장된 계획과 과제만 다시 표시한다.
- 다른 관리번호의 계획이나 과제는 표시·수정·저장하지 않는다.
- 조치계획은 여러 개 만들 수 있다. 현재 계획은 기본적으로 가장 최근 계획이며, 새 계획 생성은 명시적인 `새 조치계획` 동작으로만 가능하다.

## 구현

- 전역 `tasks` 기본 예시 값을 제거하고, 조치계획을 열 때 선택한 관리번호의 DB 계획과 과제만 상태로 채운다.
- 현재 조치계획이 있으면 PATCH API가 분석 내용과 과제 목록을 원자적으로 교체하고 감사 이력을 남긴다.
- 현재 조치계획이 없을 때만 기존 POST API가 새 계획과 과제를 생성한다.
- API는 `actionPlanId`와 관리번호 관계가 일치하는지 검증해 다른 대상의 계획을 수정할 수 없게 한다.
- 저장 성공 뒤 목록을 다시 조회하며, 실패 시 화면 상태와 DB 상태가 엇갈리지 않게 한다.

## 검증

- 서로 다른 두 관리번호에 각각 다른 과제를 저장하고 F5 후 각 대상에서 자신의 과제만 표시되는지 테스트한다.
- 과제 추가 버튼만 누른 뒤 F5하면 저장되지 않고, 저장 및 승인 요청 뒤 F5하면 저장되는지 테스트한다.
- 두 번째 저장은 새 조치계획을 생성하지 않고 기존 계획을 수정하는지 테스트한다.
